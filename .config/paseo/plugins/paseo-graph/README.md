# paseo-graph

Граф проектов, воркспейсов и агентов Paseo — как граф связей в Obsidian.
Клиентский плагин, серверной части нет.

## Что делает

Сайдбар-сёрфейс **Graph** (иконка Waypoints) и пункт Command Center
«Open Paseo graph».

**Узлы:** проект, воркспейс, агент. Размер кодирует тип, цвет — статус.
Легенда наверху.

**Рёбра:**

| Ребро | Откуда берётся |
| --- | --- |
| проект → воркспейс | `workspace.projectId` |
| воркспейс → агент | `agent.workspaceId` |
| проект → агент | запасной путь: воркспейс агента демон не отдаёт |
| агент → агент | метка `paseo.parent-agent-id` |

Все три связи читаются из данных, ничего не выводится. Ранее рисовалось
ребро «агент породил воркспейс» — по тому, что родитель и ребёнок оказались в
разных воркспейсах. Это неверно: агента можно запустить в любом существующем
воркспейсе, и такое ребро втягивало в ветку посторонних. Paseo родство
воркспейса с агентом не хранит, поэтому оно и не рисуется.

**Живой сигнал.** Пока чат работает (`status = running`), по всей его цепочке
идёт импульс: от проекта вниз через воркспейс и каждого родительского агента
до самого чата. Пульсируют и рёбра, и узлы на них. Гребень стартует наверху и
приходит к чату, потому что фаза сдвигается на каждом прыжке. Вложенность
сабагентов произвольная — цепочка обходится, а не считается фиксированным
числом прыжков; вверх идти некуда, у проекта входящих рёбер нет, там обход и
останавливается. В шапке — счётчик `N active`.

Ребро получает импульс отдельным слоем поверх себя, а не перекраской: так не
приходится разбирать и интерполировать цвета темы. Узел дышит прозрачностью —
на впадине тусклее обычного, на гребне в полную силу — и к этому добавлено
тонкое кольцо под точкой, которое набухает вместе с волной. Размер самой точки
не меняется: размер кодирует тип, так сказано в легенде.

Потолок дыхания задаёт каскад подсветки: узел, погашенный наведением на чужую
ветку, дышит еле заметно, а не вспыхивает поверх затемнения.

**Взаимодействие:** наведение подсвечивает каскад — все предки до проекта и
все потомки до последнего сабагента, остальное гаснет. Тап открывает
воркспейс или агента. Перетаскивание узлов, панорама фона, зум колесом.

**Раскладки, тоггл `tree`:**

- **дерево** (по умолчанию) — детерминированные кольца по глубине, угловой
  сектор пропорционален числу листьев. Физика не запускается, позиции
  стабильны между обновлениями.
- **физика** — силовая укладка: отталкивание по пространственной сетке,
  пружины на рёбрах, засыпает после успокоения.

**Тоггл `archive`** подмешивает архивных агентов (`includeArchived`).
У воркспейсов такого фильтра в протоколе нет: `fetch_workspaces` отдаёт только
активные, поэтому воркспейс архивного агента обычно недоступен. Такой агент
подвешивается напрямую к своему проекту — запись агента несёт `projectKey`,
а `projects.list()` даёт соответствие `projectKey → projectId`. Соответствие
точное, ничего не угадывается. Агент без `projectKey` остаётся без ребра.
Узлы «архивный воркспейс» не выдумываются: их имён у нас нет.

Данные: `paseo.projects.list()`, `paseo.workspaces.list()` и
`paseo.agents.list()`; списки воркспейсов и агентов читаются с обходом по
курсору до `hasMore = false`.

Структура приходит из каталога, жизнь — из подписок. `agents.subscribe()` и
`workspaces.subscribe()` — это слушатели уже текущего потока демона, а не
новые соединения: один слушатель обслуживает весь граф, отдельной подписки на
агента не нужно. Статус из потока перекрывает опрос — поток опережает каталог
и, пока сёрфейс смонтирован, не теряет событий. Повторы с тем же статусом
отбрасываются в обработчике, поэтому болтливый ход не даёт перерисовки на
каждое сообщение. Событие про неизвестный графу id — или любое удаление —
тянет нужный список сразу, каждый id спрашивает один раз. Опрос остался
подстраховкой на случай обрыва потока: раз в 20 секунд. Сортировка задана
явно по неизменяемым ключам: воркспейсы по `project_id`, агенты по
`created_at`; ничьи демон разрешает по неизменяемому id. На изменяемых
значениях — `activity_at`, `updated_at`, а также редактируемое `name` —
запись может переехать между страницами и потеряться. Повторный или
отсутствующий курсор — ошибка, а не тихий обрыв.

Перерисовка отделена от пересчёта: раскладка и физика трогаются только при
смене состава узлов или рёбер, обновление статусов и заголовков ничего не
двигает и не сбрасывает узлы, переставленные руками.

## Чего нет: сабагенты провайдера

Сабагенты, запущенные агентом **внутри провайдера** (Task в Claude Code,
подсессии opencode), в графе не отображаются. Это не недоделка — до них
нечем дотянуться.

- в `agents.list()` их нет: это отдельное сообщение демона
  `agent.provider_subagents.list`
- в `@getpaseo/plugin` 0.8.0 слова `subagent` нет ни в клиентских, ни в
  серверных типах
- `PaseoApi` (то, что приходит в плагин) — это `terminals`, `workspaces`,
  `projects`, `agents`, `providers`, `config`, и сырого канала к демону
  он не отдаёт

Поэтому глубина графа обрывается на агентах уровня Paseo: их родство видно,
а то, что они запустили внутри себя, — нет.

**Обходной путь, если когда-нибудь понадобится.** `@getpaseo/client`
экспортирует класс `DaemonClient` по пути `./internal/daemon-client`, и у него
есть `listProviderSubagents(parentAgentId)` — именно им пользуется UI Paseo.
Достать можно так:

1. добавить `index.server.ts` и зависимость `@getpaseo/client`
2. поднять из серверной части собственное соединение с демоном
   (`context.paseo` сырого клиента не отдаёт); аутентификации на localhost
   сейчас нет
3. объявить RPC `subagents.list`, клиент дёргает его через `useRpc`
4. подмешать результат в граф третьим типом узла

Цена: путь помечен `internal/`, то есть контракт может сломаться в любом
патче; вызов принимает одного родителя за раз, так что опрашивать всех
агентов каждые 5 секунд нельзя — тянуть только для раскрытой ветки.
И плагин перестаёт быть client-only.

## Разработка

```bash
npm install
npm run check          # typecheck + lint
npm run typecheck
npm run lint           # oxlint через bunx: ничего не пишется в node_modules
paseo plugin reload paseo-graph
paseo plugin logs paseo-graph
```

Требует Paseo >= 0.8.0. Код клиента живёт в `client/`, корень — только
`index.client.tsx`; файлы с кодом в корне запрещены сборщиком.

### Модули

| Файл | Отвечает за |
|---|---|
| `model.ts` | Из чего состоит граф и как каталог демона в него превращается |
| `signals.ts` | Какую цепочку подсвечивает работающий чат |
| `data.ts` | Чтение каталога курсорными страницами |
| `live.ts` | Подписка на поток изменений демона |
| `physics.ts` | Силовая раскладка: отталкивание по сетке, пружины, гравитация |
| `layout.ts` | Детерминированная радиальная раскладка без симуляции |
| `view.ts` | Размеры, слои, таблицы прозрачности, зум и кадрирование |
| `pulse.ts` | Бегущий гребень сигнала |
| `styles.ts` | Шкала отступов и фабрика тема-зависимых стилей |
| `node-view.tsx` | Одна точка: жесты, клавиатура, вспомогательные технологии |
| `legend.tsx` | Что означают размер и цвет |
| `graph.tsx` | Поверхность: состояние, которое связывает всё перечисленное |

`model.ts`, `signals.ts`, `physics.ts` и `layout.ts` не зависят ни от React, ни
от react-native — их можно запускать и проверять в обычном рантайме.
