# paseo-graph

Граф проектов, воркспейсов и агентов Paseo — как граф связей в Obsidian.
Клиентский плагин; серверная часть нужна только для снимка сабагентов
провайдера (см. ниже).

## Что делает

Сайдбар-сёрфейс **Graph** (иконка Waypoints) и пункт Command Center
«Open Paseo graph».

**Узлы:** проект, воркспейс, агент, сабагент провайдера. Размер кодирует
тип, цвет — статус, метка внутри точки агента — чем он запущен. Легенда
наверху; провайдеры в ней перечисляются только те, что реально есть на холсте.

**Метка провайдера.** Семейство берётся из первого сегмента `agent.provider`:
`claude/claude-opus-5` → `claude`, `opencode/openai/gpt-5.6-sol-fast` →
`opencode`. Настоящие фирменные значки у Paseo есть, но реестр хостовый:
плагину `Icon` отдаёт только имена Lucide, а SVG провайдера из клиентского кода
недостижим. Поэтому каждому семейству назначен ближайший глиф — `claude` →
Asterisk, `codex` → Atom, `opencode` → Braces, `kimi` → Moon (Kimi от
Moonshot), `gemini` → Sparkle, `copilot` → Github, `cursor` → MousePointer2,
`goose` → Bird, `grok` → Slash — а всё неопознанное остаётся ботом: уверенно
неверный значок хуже честного общего.

Значок рисуется во всю точку — не украшение внутри кружка, а кружок в
силуэте — цветом холста поверх заливки статуса, и на любом зуме без порога.
Порог пробовался и убран: на обзоре всего графа метка нужна ровно так же, как
вблизи, а на мелком масштабе глиф всё ещё читается силуэтом, хоть и теряет
штрих.

**Рёбра:**

| Ребро | Откуда берётся |
| --- | --- |
| проект → воркспейс | `workspace.projectId` |
| воркспейс → агент | `agent.workspaceId` |
| проект → агент | запасной путь: воркспейс агента демон не отдаёт |
| агент → агент | метка `paseo.parent-agent-id` |
| агент → сабагент | `parentAgentId` сабагента провайдера (тоггл `subagents`) |

Все три связи читаются из данных, ничего не выводится. Ранее рисовалось
ребро «агент породил воркспейс» — по тому, что родитель и ребёнок оказались в
разных воркспейсах. Это неверно: агента можно запустить в любом существующем
воркспейсе, и такое ребро втягивало в ветку посторонних. Paseo родство
воркспейса с агентом не хранит, поэтому оно и не рисуется.

**Живой сигнал.** Пока чат работает (`status = running`), по всей его цепочке
идёт импульс: от проекта вниз через воркспейс и каждого родительского агента
до самого чата. Пульсируют и рёбра, и узлы на них. Гребень стартует наверху и
приходит к чату, потому что фаза сдвигается на каждом прыжке. Вложенность
сабагентов произвольная — цепочка обходится, а не считается фиксированным
числом прыжков; вверх идти некуда, у проекта входящих рёбер нет, там обход и
останавливается. В шапке — счётчик `N active`.

Ребро получает импульс отдельным слоем поверх себя, а не перекраской: так не
приходится разбирать и интерполировать цвета темы. Узел дышит прозрачностью —
на впадине тусклее обычного, на гребне в полную силу — и к этому добавлено
тонкое кольцо под точкой, которое набухает вместе с волной. Размер самой точки
не меняется: размер кодирует тип, так сказано в легенде.

Потолок дыхания задаёт каскад подсветки: узел, погашенный наведением на чужую
ветку, дышит еле заметно, а не вспыхивает поверх затемнения.

**Подписи** прореживаются каждый кадр (`pickLabels` в `view.ts`): жадно по
приоритету — наведённый узел и его окрестность, затем проекты, воркспейсы,
агенты, сабагенты — подпись рисуется, только если её прямоугольник не
пересекает уже нарисованные; ушедшие за экран отбрасываются сразу. Ширина
оценивается по числу символов, без замера текста. На обзоре видны проекты,
при приближении проявляются остальные. Окрестность наведения рисуется всегда,
даже внахлёст.

**Зум:** от 0.03 до 16; подписи скрываются целиком только ниже 0.01. `fit`
нижнего предела не имеет — кадрирует любой масштаб.

**Взаимодействие:** наведение подсвечивает каскад — все предки до проекта и
все потомки до последнего сабагента, остальное гаснет. Тап открывает
воркспейс или агента. Перетаскивание узлов, панорама фона, зум колесом.

**Раскладки, тоггл `tree`:**

- **дерево** (по умолчанию) — детерминированные кольца по глубине, угловой
  сектор пропорционален числу листьев. Физика не запускается, позиции
  стабильны между обновлениями.
  - Проекты и воркспейсы стоят на фиксированных кольцах (600 и 1200 мировых
    единиц) и получают минимальный угол — 160 единиц дуги на узел, сколько бы
    листьев у них ни было. Недостающее отнимается у тяжёлых соседей
    пропорционально весу.
  - Кольца агентов и сабагентов эластичные: кольцо отодвигается наружу, пока
    ближайшие соседи на нём не окажутся хотя бы в 60 единицах. Людное кольцо
    (от 6 узлов) раскладывается в 3 ряда с шагом 140; ряды чередуются вдоль
    всего кольца по углу, а не внутри одного веера, — иначе листья соседних
    вееров на стыке встают вплотную. Граф от этого крупнее, `fit` отдаляет
    сильнее, зато точки не налезают.
- **физика** — силовая укладка: отталкивание по пространственной сетке,
  пружины на рёбрах, засыпает после успокоения.

**Тоггл `archive`** подмешивает архивных агентов (`includeArchived`).
У воркспейсов такого фильтра в протоколе нет: `fetch_workspaces` отдаёт только
активные, поэтому воркспейс архивного агента обычно недоступен. Такой агент
подвешивается напрямую к своему проекту — запись агента несёт `projectKey`,
а `projects.list()` даёт соответствие `projectKey → projectId`. Соответствие
точное, ничего не угадывается. Агент без `projectKey` остаётся без ребра.
Узлы «архивный воркспейс» не выдумываются: их имён у нас нет.

Данные: `paseo.projects.list()`, `paseo.workspaces.list()` и
`paseo.agents.list()`; списки воркспейсов и агентов читаются с обходом по
курсору до `hasMore = false`.

Структура приходит из каталога, жизнь — из подписок. `agents.subscribe()` и
`workspaces.subscribe()` — это слушатели уже текущего потока демона, а не
новые соединения: один слушатель обслуживает весь граф, отдельной подписки на
агента не нужно. Статус из потока перекрывает опрос — поток опережает каталог
и, пока сёрфейс смонтирован, не теряет событий. Повторы с тем же статусом
отбрасываются в обработчике, поэтому болтливый ход не даёт перерисовки на
каждое сообщение. Событие про неизвестный графу id — или любое удаление —
тянет нужный список сразу, каждый id спрашивает один раз. Опрос остался
подстраховкой на случай обрыва потока: раз в 20 секунд. Сортировка задана
явно по неизменяемым ключам: воркспейсы по `project_id`, агенты по
`created_at`; ничьи демон разрешает по неизменяемому id. На изменяемых
значениях — `activity_at`, `updated_at`, а также редактируемое `name` —
запись может переехать между страницами и потеряться. Повторный или
отсутствующий курсор — ошибка, а не тихий обрыв.

Перерисовка отделена от пересчёта: раскладка и физика трогаются только при
смене состава узлов или рёбер, обновление статусов и заголовков ничего не
двигает и не сбрасывает узлы, переставленные руками.

## Сабагенты провайдера (тоггл `subagents`)

Сабагенты, запущенные агентом **внутри провайдера** (Task в Claude Code,
`@librarian`/`@explore` в opencode), рисуются маленькими узлами на ребре
`spawn` от своего агента. Подпись — `description`, при наведении — `subtitle`
(модель · effort · токены). Статусы переведены на имеющуюся палитру:
completed → done, canceled → idle. Работающий сабагент пульсирует, клик
открывает его агента. Вложенность по `parentSubagentId` поддержана, но
встроенные Claude и opencode сейчас отдают `null`, так что граф плоский:
агент → сабагенты.

Данные приходят двумя путями:

1. **Живой поток** — публичный `usePaseo().observeEvents(["agent.provider_subagents.update"])`,
   одна подписка на всех агентов: `upsert` / `remove` / `timeline`.
   Уже существующих сабагентов поток не переигрывает.
2. **Снимок** — `PaseoApi` списка сабагентов не отдаёт, поэтому серверная часть
   плагина (`index.server.ts` → `server/subagents.ts`) держит своё соединение с
   демоном через `@getpaseo/client/internal/daemon-client` и отвечает на RPC
   `subagents.list`. Клиент шлёт родителей пачками по 25, сервер опрашивает
   демон в 4 потока (таймаут 15 с на запрос). Граф рисуется сразу, сабагенты
   досыпаются по мере ответов, прогресс в шапке: `· subagents N/M (K failed)`.
   Поток и снимок сливаются по `updatedAt` — побеждает более свежий.

**Почему по умолчанию видны не все.** Демон хранит сабагентов только в памяти
(`ProviderSubagentStore`) и наполняет их, когда агент загружается и
переигрывает историю провайдера. На диске их нет. После рестарта демона почти
все агенты — `closed` (не архивные, просто не загружены), и сабагентов у них
нет, пока агент не поднимут. Поэтому снимок по умолчанию спрашивает только
загруженных агентов.

**Тоггл `load all`** (виден, пока включён `subagents`) спрашивает и `closed`.
Цена: демон поднимает каждого такого агента из хранилища в режиме
`interactive` — статус в UI меняется `closed` → `idle`, opencode-агенты
захватывают `opencode serve` на свой `cwd`, агент остаётся в памяти до
рестарта демона. Токены не тратятся, ничего не запускается в работу. Пока
идёт такой скан, на кнопке крутится спиннер. Выключение тоггла отменяет ещё не
отправленные пачки. Архивных агентов демон отвергает (`Agent is archived`)
при любом режиме — их сабагентов не достать.

**Ограничения.**

- Путь `internal/` — контракт может сломаться в любом патче Paseo.
- Адрес демона — `daemon.listen` из `~/.paseo/config.json`, переопределяется
  `PASEO_GRAPH_DAEMON_URL`. Удалённый демон или демон с паролем не
  поддерживаются.
- Упавшие пачки не повторяются, пока тоггл не выключить и включить.
- Нужен демон Paseo >= 0.9 (события `agent.provider_subagents.*`) — поэтому
  это минимальная версия всего плагина в `paseo-plugin.json`.

## Разработка

```bash
npm install
npm run check          # typecheck + lint
npm run typecheck
npm run lint           # oxlint через bunx: ничего не пишется в node_modules
paseo plugin reload paseo-graph
paseo plugin logs paseo-graph
```

Требует Paseo >= 0.9.0. Код клиента живёт в
`client/`, сервера — в `server/`, общие RPC-контракты — в `shared/`; в корне
только `index.client.tsx` и `index.server.ts`.

### Модули

| Файл | Отвечает за |
|---|---|
| `model.ts` | Из чего состоит граф и как каталог демона в него превращается |
| `signals.ts` | Какую цепочку подсвечивает работающий чат |
| `data.ts` | Чтение каталога курсорными страницами |
| `live.ts` | Подписка на поток изменений демона |
| `physics.ts` | Силовая раскладка: отталкивание по сетке, пружины, гравитация |
| `layout.ts` | Радиальная раскладка: кольца хабов, эластичные кольца, ряды |
| `focus.ts` | Раскладка поддерева в фокусе |
| `view.ts` | Размеры, слои, зум, кадрирование, метки, отбор подписей |
| `subagents.ts` | Сабагенты: живой поток + пачечный снимок через RPC |
| `spinner.tsx` | Текстовый спиннер для кнопок |
| `pulse.ts` | Бегущий гребень сигнала |
| `styles.ts` | Шкала отступов и фабрика тема-зависимых стилей |
| `node-view.tsx` | Одна точка: жесты, клавиатура, вспомогательные технологии |
| `legend.tsx` | Что означают размер, цвет и метка внутри точки |
| `graph.tsx` | Поверхность: состояние, которое связывает всё перечисленное |
| `server/subagents.ts` | Соединение с демоном и опрос `listProviderSubagents` |
| `shared/subagents.ts` | Схема сабагента и RPC `subagents.list` |

`model.ts`, `signals.ts`, `physics.ts` и `layout.ts` не зависят ни от React, ни
от react-native — их можно запускать и проверять в обычном рантайме.
