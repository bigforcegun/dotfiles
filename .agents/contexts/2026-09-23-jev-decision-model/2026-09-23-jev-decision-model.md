# Jev / System One decision model

[[DOTFILES]]

## Purpose

Оценить TypeSafe Jev как дешёвый калиброванный классификатор и решить, куда его
встраивать в свои харнессы.

Jev вышел 2026-09-15, весь материал собран 2026-09-22/23 — экосистеме около недели,
цифры вендора независимо не подтверждены. Читать с поправкой на возраст.

## Что уже установлено

- Jev — не LLM: на вход состояние программы, на выход типизированное вероятностное
  решение. Три примитива: `noul`, `choice`, `score`. Текста не генерирует.
- $0.042/M input, **output бесплатный**, 70–500 мс. Через наш OpenRouter измеренный
  сторонними p50 = 380 мс и контекст урезан до 32k против 64k у вендора.
- «Не может галлюцинировать» — гарантия области значений, а не правильности. Экономит
  слой retry/parse, но не отменяет верификацию.
- Калибровка — свойство ансамбля, не отдельного ответа. Пороги считаются из цены
  ошибок; серая зона обязательна.
- Из четырёх наших харнессов только **OpenCode** имеет пригодную точку входа для
  дословной компакции.

## Load policy

Грузить, когда речь про Jev/System One, про дешёвую классификацию в агентском пайплайне
или про компакцию контекста в наших харнессах.

Для одного вопроса хватает этой записки; заметки открывать только по делу — они длинные.

Что не трогать по ходу: роутинг моделей. Слой самый шумный и хрупкий, апстрим OpenCode
свой PR на эту тему закрыл. Сторонние плагины Jev для OpenCode не ставить — блокеры
перечислены в [[2026-09-23-jev-decision-model-harnesses]].
