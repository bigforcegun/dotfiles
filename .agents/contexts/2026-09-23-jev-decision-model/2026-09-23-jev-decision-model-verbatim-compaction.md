# Verbatim-компакция контекста

[[2026-09-23-jev-decision-model]]

Самая содержательная идея недели вокруг Jev — и она не про классификацию. Точки
подключения см. в [[2026-09-23-jev-decision-model-harnesses]].

## Почему обычная компакция плоха

Стандартный путь: контекст распух → вспомогательная LLM пересказывает историю →
пересказ заменяет оригинал.

Проблема в асимметрии потерь:

- **Выбросил нужное** — агент замечает нехватку и перезапускает тул. Цена: один вызов.
- **Пересказал неточно** — агент работает с ложным представлением и **не знает об этом**.
  Цена: неограниченная.

Пересказ stacktrace — потеря номеров строк. Пересказ `git status` — потеря точных путей.
Пересказ ошибки — потеря той единственной строки, по которой её можно нагуглить.
Суммаризатор при этом отработает безупречно и сохранит суть; беда в том, что у
стектрейса суть и есть его буква.

**Идея: убрать третье состояние.** Либо дословно, либо нет вообще. Пересказа не существует.

## Школа А — два вопроса (читал в коде)

`picaye/jev-compaction`, `deadczarvc/hermes-jev-compaction`.

Кандидаты на удаление — **только tool calls и их результаты**. Текст пользователя и
ассистента не трогается никогда, ни при каких вероятностях.

На каждый непиненый вызов два `noul`:

| Вопрос | Смысл |
|---|---|
| `keepCall` | важно ли ещё, что этот вызов вообще был |
| `keepResult` | нужно ли содержимое — **и не даст ли повторный запуск тула то же самое** |

Вторая половина `keepResult` — самая умная деталь конструкции: в вопрос встроена
**восстановимость**. `ls` выкидывается смело, перезапуск вернёт то же. Результат
сетевого запроса или недетерминированной команды — нельзя, он невоспроизводим.

Политика при пороге (по умолчанию 0.5):

```
keepResult >= t   → оставить вызов и результат целиком
keepCall   >= t   → оставить вызов, результат усечь до 300 символов + пометка
иначе             → удалить оба
```

**Детерминированные страховки поверх вероятностей:**

- **Protected tools.** `write_file`, `patch`, `memory`, `skill_manage`, `todo`,
  `cronjob_manage`, `process_manage` меняют состояние. Если Jev советует удалить — вызов
  «спасается» принудительно, усекается только результат. Модель советует, код решает.
- **Первое сообщение** целиком неприкосновенно — там задача.
- **Последние `--preserve` сообщений** (по умолчанию 6) неприкосновенны.
- `--dry-run` — построить карту решений без единого вызова API.

**Измерено на реальных сессиях:** сокращение **68–98.4% от числа сообщений**, ноль
осиротевших записей, побайтовая идентичность сохранённого текста. Оговорка: это доля
**сообщений**, не токенов — не одно и то же, вторую цифру никто не опубликовал.

## Школа Б — четыре вопроса, пять действий

`keeltrace/hermes-jev`, из официального каталога плагинов Hermes Agent. Оценивается не
«оставить/убрать», а четыре независимые семантические величины:

| Вопрос | Что оценивает |
|---|---|
| `needed_again` | понадобится ли ещё в рамках текущей цели |
| `exact_required` | нужен дословный контент или хватит provenance |
| `superseded` | перекрыто ли более свежим состоянием |
| `conflict` | участвует ли в неразрешённом противоречии |

Детерминированный код превращает их в пять действий:

- **KEEP_EXACT** — дословно;
- **PIN** — держать, пока активен lease или не разрешён конфликт;
- **ANCHOR** — тело заменяется на provenance + хеш + префикс + указатель восстановления;
- **DROP** — только для детерминированно восстановимого, малоценного и перекрытого;
- **REHYDRATE** — вернуть заякоренное из локального журнала.

`ANCHOR` — то, чего нет в школе А: не «удалить» и не «оставить целиком», а «оставить
честную ссылку с хешем и возможностью восстановить». Компромисс без пересказа.

**Lifecycle leases:** свидетельство о невосстановимом сбое автоматически получает lease
`until_verification_pass` и не может быть выброшено, пока реальная верификация не вернёт
`PASS`. То есть «мы уже пробовали, не сработало» переживает компакцию гарантированно —
самая дорогая в потере разновидность контекста.

Плагин выставляет восемь тулов: `jev_decide`, `jev_rank`, `jev_verify`, `jev_assess`,
`jev_context_curate`, `jev_context_rehydrate`, `jev_stats`, `jev_nervous_event`.

## Почему Jev, а не LLM

Решение принимается **по каждому tool call отдельно**, их в длинной сессии сотни, все
вопросы уходят одним запросом параллельно. LLM-компактор — один большой дорогой вызов с
общим пересказом; здесь сотни независимых дешёвых суждений, каждое со своей вероятностью,
которую можно откалибровать.

## Что проверить до переноса к себе

1. **Порог 0.5 — заглушка, а не рекомендация.** Калибруется на своих сессиях.
   `--dry-run` даёт shadow-режим бесплатно, старые транскрипты — готовая выборка.
   Методика в [[2026-09-23-jev-decision-model-usage]].
2. **Точка подключения.** Hermes даёт формальный ABC `ContextEngine`, плагин выбирается
   явно через `context.engine`, авто-активации нет. У OpenCode аналог —
   `experimental.chat.messages.transform`, но он вызывается на каждой отправке, а не при
   переполнении: триггер и кеш вердиктов по `callID` придётся писать самим.
3. **Асимметрия ошибок остаётся.** Выброшенный невосстановимый результат не вернуть.
   Protected-list и leases — несущая конструкция, а не украшение. Свой список
   state-changing тулов составить до первого запуска.
4. **Качество исходников.** В экосистеме минимум четыре почти одинаковых репозитория
   «Jev compaction for Hermes» от разных авторов с совпадающими формулировками README.
   Похоже, значительная часть сгенерирована агентами: идеи брать можно, код — только читая.
