# Трек 4. Оркестрация через Paseo

## Первый урок: внешний и внутренний уровни

Paseo управляет отдельными сессиями coding agents, workspace и их жизненным циклом. Внутри OpenCode-сессии с OMO основной агент может отдельно делегировать через task. Это два уровня оркестрации; не нужно использовать оба на каждой маленькой задаче. Последнее является рекомендацией курса. [S3–S5, S9–S11 в [[2026-10-03-omo-learning-sources]]]

```text
Paseo: основной агент
  ├─ исследователь: общие файлы, только чтение
  └─ исполнитель: отдельный workspace/worktree
       └─ внутренние делегаты OMO, если нужны
После реализации: независимый проверяющий в workspace исполнителя
```

Это пример организации работы, не обязательная топология продукта. [S9]

## Четыре проверки до запуска

1. **Host:** где работает daemon и где находятся репозиторий и provider. CLI поддерживает явный `--host`; внедрённые Paseo tools работают на host основного агента. [S9, S11]
2. **Workspace:** какой каталог будет видеть агент. Для независимых правок выбрать отдельный worktree; read-only исследователи могут работать с общими файлами. [S9, S10]
3. **Профиль:** посмотреть доступные профили и заметки When to use на целевом host. В MCP create_agent профиль не передаётся как поле profile: его настройки преобразуются в параметры запуска. [S11, S14]
4. **Результат:** описать границы, запреты, доказательства и момент остановки. Это рекомендация по постановке задачи.

Профили принадлежат host; их изменение влияет на будущие запуски, а не обновляет уже работающего агента. Перенос агента в другой workspace не делает его независимым top-level агентом: parentage меняется отдельным detach. [S10, S11, S14]

## Безопасный шаблон поручения

> Через Paseo изучи доступные профили и их заметки. Для реализации выбери подходящий профиль и отдельный workspace с worktree. Измени только модуль X, не меняй публичный контракт Y. Выполни целевые проверки. Верни список изменений, результаты проверок и нерешённые вопросы. Не создавай heartbeat. После результата остановись.

Шаблон не выполнялся в исследовании. Для начала практики нужны реальная задача и выбранное место работы.

## Продолжить, а не создать дубликат

Paseo адресует существующую сессию по agent ID:

```text
send_agent_prompt({ agentId: "<Paseo agent ID>", prompt: "Проверь граничный случай и сообщи результат" })
```

CLI предлагает `paseo send <id> "..."`. Для удалённой цели тот же вызов должен явно учитывать `--host`. Это примеры документированного интерфейса, не исполненные команды. ID Paseo нельзя подставлять в OMO background_output. [S11]

## Советник, handoff, review

- Advisor: ограниченное второе мнение, не передача всей ответственности.
- Handoff: передача работы вместе с контекстом, решениями, ограничениями и следующим шагом.
- Reviewer: отдельная проверка готового изменения; в documented workflow видит файлы исполнителя, но начинает свежий разговор. [S9, S12]

Рекомендация: перед объединением изменений проверять diff и результат, а не только сообщение «готово». Изоляция worktree предотвращает общую рабочую директорию, но сама по себе не доказывает отсутствие логических конфликтов.

## Heartbeat и schedule

| Механизм | Что происходит |
|---|---|
| Heartbeat | Периодически отправляет prompt той же сессии с её разговором |
| Schedule | Создаёт нового агента на очередном запуске |

Для heartbeat заранее определить полезный следующий шаг, срок действия и удаление после завершения. Не добавлять его автоматически к учебному заданию: внешнее возобновление и внутренний OMO continuation могут существовать одновременно. Наличие обоих механизмов не доказывает, что конкретный агент сейчас зациклен. [S9, S12]

## Упражнение

Нужно независимо исправить два модуля, затем проверить оба изменения. Выбрать: общая директория или отдельные worktree; кто меняет файлы; кто проверяет; где хранится итог; что останавливает работу. Обосновать, нужен ли вообще heartbeat.
