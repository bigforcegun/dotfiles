# Трек 1. OMO для пользователя

## Первый урок: кто за что отвечает

OpenCode предоставляет сессии, модели, инструменты, CLI и серверный API. OMO добавляет агентные роли, делегирование и рабочие процедуры. Skills подключают инструкции для определённой задачи. AGENTS.md и prompt выбранного агента дополняют правила поведения. Paseo управляет внешними сессиями агентов и местом их работы. [S1, S3–S7, S9–S11, L3–L4 в [[2026-10-03-omo-learning-sources]]]

```text
Ты → Paseo → OpenCode с OMO → основной агент → делегаты
                                ↑
                       инструкции и skills
```

Это упрощённая схема нашего учебного сценария: OpenCode можно использовать и без Paseo. Skills задают процедуры, а не являются отдельными моделями.

## Как выбирать режим

Ниже рекомендации курса, а не обязательный автоматический маршрутизатор:

| Задача | Начальная формулировка |
|---|---|
| Понять термин | «Только объясни, ничего не меняй; один пример» |
| Небольшая правка | Обычный запрос с конкретным ожидаемым результатом |
| Сложная реализация | ulw / ultrawork и ясный критерий готовности |
| Сначала согласовать план | Явно попросить ulw-plan; реализацию запускать отдельно |
| Глубоко исследовать тему | Явно попросить ulw-research, указать границы и формат |

В документации OMO `ulw`/`ultrawork` описаны как текстовые триггеры, не имена отдельного исполнителя. Наличие слова-триггера не гарантирует качество результата. Конкретное написание `ultraresearch` в нашем запросе интерпретировано агентом, а не проверено как parser keyword. [S13, L4]

## Главные роли

- Sisyphus: основной оркестратор.
- Hephaestus: автономный исполнитель; текущая сессия использует эту роль.
- Prometheus: планировщик; его обязательный prompt загружает ulw-plan и запрещает подменять планирование реализацией.
- Atlas: исполнитель согласованного плана в workflow ulw-execute.
- Explore: исследование локального кода; Librarian: внешняя документация; Oracle: консультация. Это роли делегатов, не обязательные ручные шаги пользователя. [S1, S4, S13, L7]

## Минимальный набор имён

| Имя | Что подтверждено |
|---|---|
| ulw-plan | Skill установлен и доступен в этой сессии; пишет план, не реализацию |
| /ulw-execute | Есть определение built-in command в установленном bundle; также установлен одноимённый skill |
| /goal | В bundle есть команда управления целью |
| /stop-continuation | В bundle есть команда остановки автоматических продолжений текущей сессии |
| /handoff | В bundle есть команда подготовки контекста для новой сессии; не путать с передачей через Paseo |
| ulw-research | Skill глубокого исследования, загруженный для этого курса |

Основание: L4, L7. Наличие в bundle не гарантирует отображение в каждом UI или отсутствие переопределения пользовательской командой. Меню именно текущего клиента отдельно не снималось; доступность skills видна в инструментах сессии.

### Почему здесь нет /start-work

Первая волна нашла это имя в документации dev. Точечная проверка установленного dist/index.js обнаружила встроенную регистрацию ulw-execute; совпадений start-work в этом bundle нет. Поэтому не учим /start-work как команду данной установки и не объявляем её псевдонимом. Это не утверждение о всех исторических версиях OMO. [L7]

## Сценарий без лишней церемонии

> Объясни, чем планирование отличается от выполнения. Ничего не меняй. Используй пример маленькой правки и заверши после объяснения.

Если нужна реализация, следующий запрос должен назвать изменение и проверяемый результат. Для большого задания можно использовать отдельный план, но маленький вопрос не обязан проходить через весь конвейер.

## Упражнение

Назвать, кто отвечает за каждое действие: открыть ещё одну сессию в другом worktree; найти функцию в репозитории; запустить внутреннего делегата; задать стиль ответа. Ответ пользователя и разбор пока не получены.
