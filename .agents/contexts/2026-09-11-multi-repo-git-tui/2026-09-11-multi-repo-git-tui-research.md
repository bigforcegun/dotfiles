# Multi-repo git TUI — мини-ресерч

[[2026-09-11-multi-repo-git-tui]]

## Вопрос

Нужен TUI/CLI для управления кучей git-репозиториев. Четыре сценария:

1. посмотреть полный список репозиториев;
2. поглядеть ворктри, если есть;
3. поглядеть отставание от мастера;
4. глобальный fetch / pull мастеров.

## Вывод

Единого инструмента под все четыре сценария не существует. Ворктри — слепое пятно
у всех multi-repo инструментов: они знают про репозитории, но не про воркtree'и внутри них.
Рабочая связка — **gita** (сценарии 1, 3, 4) + **gwq** (сценарий 2).

## Ключевые наблюдения

- **`gitbatch` — ловушка.** Это единственный кандидат, буквально являющийся TUI для
  множества репозиториев, ровно под исходный запрос. Последний коммит — май 2023.
  Как основу для ежедневного workflow брать не стоит.
- **`gita` жив и точно ложится на сценарии 1/3/4.** `gita add -a <dir>` рекурсивно
  находит репозитории, `gita ll` даёт список с веткой и ahead/behind,
  `gita super fetch` / `gita pull` работают по всем параллельно, есть группировка `-g`.
- **`gwq` — единственное про ворктри глобально.** Видит worktree'и по всем репозиториям
  сразу, навигация через fzf. В brew нет: `go install github.com/d-kuro/gwq/cmd/gwq@latest`.
  Позиционируется автором под параллельные AI-coding workflow — совпадает с тем,
  как ворктри используются в этом репозитории (см. [[DOTFILES]] и конвенцию
  `.git-worktrees/dotfiles/<branch>`).
- **`lazygit` уже установлен** и остаётся инструментом «зайти внутрь конкретного репо».

## Альтернатива: свой скрипт

`gita ll` + `git worktree list` в цикле — примерно 15 строк в `~/.dotfiles/bin`,
ноль зависимостей, полный контроль над форматом вывода. Стоит рассмотреть, если
связка из двух чужих инструментов окажется избыточной.

## Команды установки

```bash
brew install gita
go install github.com/d-kuro/gwq/cmd/gwq@latest
```
